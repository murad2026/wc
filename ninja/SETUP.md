# Часть 1. Supabase — выполнить SQL

Пока это не сделано, форма заказа и анкета эксперта показывают честную ошибку с предложением написать на почту. Ничего не ломается, но и не работает.

## Шаг за шагом

1. Открыть **supabase.com**, войти, выбрать проект `nhkwgulokiwqwfrynmkx` (тот же, где лежат подписи конституции).
2. В левом меню — **SQL Editor** (иконка `>_`).
3. Нажать **New query**.
4. Открыть в репозитории файл **`sql/orders.sql`**, скопировать **целиком**, вставить в окно.
5. Нажать **Run** (или Ctrl/Cmd + Enter).
6. Внизу должно появиться зелёное **Success. No rows returned**. Это правильный ответ: мы создавали таблицу, а не запрашивали данные.
7. Повторить шаги 3–6 для файла **`sql/experts.sql`**.

Порядок между файлами не важен, они друг от друга не зависят.

## Проверить, что получилось

**Table Editor** в левом меню → в списке должны появиться две таблицы: `orders` и `experts`.

Дальше живая проверка, она же первый тест формы:

1. Открыть `/ninja/order.html`, заполнить любыми данными, отправить.
2. Должен появиться номер вида **VN-K4M2QX**.
3. В Table Editor → `orders` появится строка.
4. Открыть `/ninja/status.html`, ввести этот номер — покажет стадию «Заказ принят».
5. Тестовую строку потом удалить прямо в Table Editor.

Если на шаге 2 вместо номера появилась ошибка — SQL не выполнился или выполнился с ошибкой. Смотреть в SQL Editor вкладку с результатом последнего запроса.

## Если Run выдал красным

| Текст ошибки | Что значит |
|---|---|
| `relation "orders" already exists` | Не ошибка. Таблица уже создана, `create table if not exists` её не тронул |
| `policy ... already exists` | Скрипт запускали второй раз. Политики не пересоздаются — либо удалить их в Authentication → Policies, либо просто пропустить |
| `permission denied` | Вошли не в тот проект или не под владельцем |
| `syntax error at or near` | Скопирована часть файла. Копировать целиком, от первой строки до последней |

## Чего в этих скриптах намеренно нет

Ни одной команды `update` для анонимного доступа. Стадию заказа и статус эксперта двигаем **только руками в панели** — с сайта их изменить нельзя ни при каком запросе.

## Что делать руками после каждой заявки эксперта

1. Проверить личность и трудовую историю.
2. В Table Editor → `experts` проставить `code` (KAGE-03, KAGE-04…) и `access_code` вида `EX-` плюс шесть символов.
3. **Выслать `access_code` эксперту** — по нему он смотрит свой статус на `/ninja/me.html`.
4. Двигать `status`: `applied` → `exam` → `shadow` → `solo`. Bar Raiser можно ставить `solo` сразу.
5. После каждого сданного отчёта обновлять `ontime_pct` и `avg_hours`.

## Про ключи

На страницах лежит **publishable** ключ — он и должен быть публичным, на то и рассчитан. Ключ `service_role` не должен попасть в репозиторий никогда: он обходит все политики и права на колонки, то есть открывает почты клиентов и настоящие имена экспертов.

# Часть 2. Домен на GoDaddy

Домен куплен. Дальше три этапа, и **порядок между ними менять нельзя**.

## Почему порядок важнее всего

Мы уже теряли theworldconstitution.org: сняли CNAME, пока DNS ещё смотрел на GitHub, домен стал «висящим», и его подхватил чужой сайт с казино. Сутки на восстановление.

**Всегда:** верификация домена в аккаунте → потом DNS → потом Custom domain в репозитории.

## Этап 1. Отдельный репозиторий

GitHub Pages разрешает один домен на репозиторий, а у `murad2026/wc` он занят под theworldconstitution.org.

1. Создать публичный репозиторий, например `murad2026/verified-ninja`.
2. Скопировать в его корень содержимое папки `ninja/`: восемь HTML-файлов, `app.css`, `i18n.js`, папку `lang/`.
3. **Файлы `*.md` не копировать.** В `SERVICES.md`, `SCORING.md`, `EXPERT_ONBOARDING.md`, `GTM.md` лежат формула балла, планка допуска и тексты писем — клиенту это не адресовано, а репозиторий публичный.
4. Рядом положить файл с именем **`CNAME`** (без расширения), внутри одна строка:
   ```
   verified.ninja
   ```
5. Settings репозитория → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.

## Этап 2. Верификация домена — до всякого DNS

1. GitHub → **аватар справа сверху** → Settings (настройки аккаунта, не репозитория).
2. Слева **Pages** → **Add a domain** → ввести `verified.ninja` → Add domain.
3. GitHub покажет две строки:
   - имя записи: `_github-pages-challenge-murad2026`
   - значение: длинная строка из букв и цифр

**Значение копировать кнопкой, целиком.** В прошлый раз мы вписали в поле значения посторонний текст и полдня не понимали, почему верификация висит.

## Этап 3. DNS в GoDaddy

1. Войти на **godaddy.com** → **My Products** → рядом с доменом кнопка **DNS** → **Manage DNS**.
2. **Сначала удалить то, что GoDaddy поставил сам:** запись `A` на `@` с их парковочным адресом и `CNAME` на `www`, если он ведёт на их страницу. Иначе домен продолжит показывать заглушку.
3. Проверить **Forwarding** — если включена переадресация домена, выключить. Она перебивает A-записи.
4. Добавить записи кнопкой **Add New Record**:

| Тип | Name | Value | TTL |
|---|---|---|---|
| TXT | `_github-pages-challenge-murad2026` | значение из шага 2 этапа 2 | 1 час |
| A | `@` | `185.199.108.153` | 1 час |
| A | `@` | `185.199.109.153` | 1 час |
| A | `@` | `185.199.110.153` | 1 час |
| A | `@` | `185.199.111.153` | 1 час |
| CNAME | `www` | `murad2026.github.io` | 1 час |

> В поле Name у GoDaddy пишется только имя без домена: `@` означает сам `verified.ninja`, `www` означает `www.verified.ninja`. Полное имя писать не нужно, GoDaddy добавит его сам.

5. Вернуться в GitHub → Settings аккаунта → Pages → **Verify**. Обычно проходит за несколько минут, иногда до часа.
6. Дождаться зелёного **Verified**.

## Этап 4. Включить домен в репозитории

Только после зелёной галочки:

1. Settings репозитория `verified-ninja` → Pages → **Custom domain**: `verified.ninja` → Save.
2. Подождать, пока GitHub выпустит сертификат (от нескольких минут до часа).
3. Поставить галочку **Enforce HTTPS**. Пока она серая — сертификат ещё выпускается, это нормально.

## Проверка

```
https://verified.ninja        → открывается сайт
https://www.verified.ninja    → перекидывает на без www
http://verified.ninja         → перекидывает на https
```

Плюс с телефона: главная, профили экспертов, форма заказа, статус, анкета. Все пять языков переключаются.

## После переезда

1. **Почта `hello@verified.ninja`** — она указана на всех страницах. Пока её нет, мы обещаем то, чего не выполняем. У GoDaddy есть переадресация почты, либо подключить Google Workspace.
2. На странице Рынка основного сайта ссылка слоя Verified Talent должна вести на `https://verified.ninja`, а не на `ninja/`. Это поле `url` в шести файлах `docs/lang/*.json` — скажи, поправлю.
3. Старый путь `theworldconstitution.org/ninja/` **не удалять**. Оставить страницу с редиректом: на него уже могут быть ссылки.

## Чего не делать

- Не менять DNS до зелёного «Verified».
- Не снимать CNAME, пока DNS смотрит на GitHub. Сначала DNS, потом CNAME — в обратном порядке домен повисает и его может забрать кто угодно.
- Не включать у GoDaddy их «Website Builder» или парковку на этом домене.
