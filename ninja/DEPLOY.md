# Переезд Verified.Ninja на свой домен

> Сейчас сайт живёт по адресу `theworldconstitution.org/ninja/`. Это временно и неправильно: клиент, которому мы обещаем, что материнский проект его не касается, видит его прямо в адресной строке.

---

## Главное правило, выученное дорого

**Домен верифицируется в аккаунте GitHub ДО того, как на него направляется DNS.**

Мы уже наступали на это с theworldconstitution.org: сняли CNAME, пока DNS ещё смотрел на GitHub, домен оказался «висящим», и его подхватил чужой сайт с казино. Восстановление заняло день и стоило нервов.

Порядок всегда такой: **сначала верификация домена → потом DNS → потом Custom domain в настройках репозитория.** Не наоборот.

---

## Почему нужен отдельный репозиторий

GitHub Pages разрешает **один custom domain на репозиторий**. У `murad2026/wc` он уже занят под theworldconstitution.org. Поэтому Verified.Ninja либо получает свой репозиторий, либо уезжает на другой хостинг.

---

## Вариант A — отдельный репозиторий на GitHub Pages

Бесплатно, тот же механизм, что и у основного сайта.

1. Создать репозиторий, например `murad2026/verified-ninja`, публичный.
2. Скопировать в его корень содержимое папки `ninja/` из этого репозитория: восемь HTML-страниц, `app.css`, `i18n.js`, папку `lang/`. Файлы `*.md` не копировать — это внутренние документы, клиенту их видеть незачем.
3. Положить рядом файл `CNAME` с одной строкой:
   ```
   verified.ninja
   ```
4. **Сначала верификация.** GitHub → Settings аккаунта → Pages → Add a domain → `verified.ninja`. GitHub выдаст TXT-запись вида
   `_github-pages-challenge-murad2026` со значением из тридцати с лишним символов.
   **Значение копировать целиком, ровно как показано.** В прошлый раз мы вписали в поле значения слова вместо самой строки, и верификация не проходила полдня.
5. Дождаться зелёного «Verified».
6. Только теперь DNS у регистратора:

   | Тип | Имя | Значение |
   |---|---|---|
   | A | `@` | 185.199.108.153 |
   | A | `@` | 185.199.109.153 |
   | A | `@` | 185.199.110.153 |
   | A | `@` | 185.199.111.153 |
   | CNAME | `www` | `murad2026.github.io` |

7. Settings репозитория → Pages → Source: ветка + корень; Custom domain: `verified.ninja`; включить **Enforce HTTPS** (появится через несколько минут, после выпуска сертификата).

---

## Вариант B — Cloudflare Pages

Если не хочется второго репозитория: Cloudflare Pages умеет собирать **подпапку** того же репозитория.

- Подключить репозиторий `murad2026/wc`
- Build command: пусто
- Build output directory: `ninja`
- Custom domain: `verified.ninja`

DNS Cloudflare пропишет сам. Плюс: одна кодовая база, публикуется тем же коммитом. Минус: ещё один сервис в схеме.

---

## После переезда — обязательно

1. **Абсолютные ссылки в письмах и подписях** заменить на новый домен.
2. На `theworldconstitution.org/market.html` ссылка на слой Verified Talent должна вести на `https://verified.ninja`, а не на `ninja/`. Поле `url` в шести словарях `docs/lang/*.json`.
3. Старый путь `theworldconstitution.org/ninja/` **не удалять**, а оставить страницу-редирект: на него уже могут быть ссылки.
4. Почта `hello@verified.ninja` должна работать — она указана на всех страницах. Пока домен без почты, это обещание, которое мы не выполняем.
5. Проверить с телефона: главная, профили, форма заказа, статус, анкета эксперта. Все пять языков переключаются.

---

## Чего делать нельзя

- Направлять DNS до верификации домена в аккаунте.
- Снимать CNAME, пока DNS смотрит на GitHub. Сначала DNS, потом CNAME — в обратном порядке домен становится «висящим» и его может забрать кто угодно.
- Копировать в публичный репозиторий `*.md` из папки `ninja/`: там внутренние правила, формула балла и планка допуска. Клиенту это не адресовано.
