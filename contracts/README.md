# Canon — статья 2 как контракт

Что здесь: `Canon.sol` — контракт, который делает ядро конституции неизменяемым
не по договорённости, а по устройству, и оставляет форк единственным способом
это ядро поменять.

## Что именно защищено

Разделение проходит по одной линии:

| | Как хранится | Кто может изменить |
|---|---|---|
| Ядро, статьи 1–6 | `immutable bytes32` — в байт-коде, не в storage | **никто** |
| Изменяемая часть | обычная переменная | стюарды, через таймлок 7 дней |
| Кто принял | подпись самого принявшего | только он сам |
| Список форков | append-only | кто угодно, отказать нельзя |

`immutable` в Solidity — не соглашение и не модификатор доступа. Значение
вшивается в код при деплое и лежит вне storage; инструкции, которая могла бы
его перезаписать, в контракте не существует. Скомпрометированный ключ стюардов
не меняет ядро. Захваченное голосование не меняет ядро. Единственное, что можно
сделать, — развернуть другой контракт, и это видно всем.

## Три решения, на которых всё держится

**Нет прокси.** Это главное. Подавляющее большинство «неизменяемых» контрактов
в проде стоят за proxy, и админ меняет логику одной транзакцией, сохраняя адрес.
Пользователь при этом продолжает видеть тот же адрес и думать, что читает тот же
код. Здесь адрес и есть код: `delegatecall` не используется, апгрейд невозможен.

**Ядро нельзя переголосовать.** В контракте нет функции, меняющей `coreHash`,
поэтому и голосование по нему не предусмотрено: исполнить его результат нечем.
Это сознательно — голосование, которое ничего не может, честнее голосования,
которое якобы может.

**Форк нельзя запретить.** `noteFork` проверяет только родство и не имеет права
вето. Ни стюарды, ни принявшие не могут отклонить регистрацию. Статья 12
работает ровно в ту сторону, в которую заявлена: две версии живут, ни одна не
объявляет другую вне закона.

## Как принятие связано с потерей легитимности

Список принявших живёт внутри конкретного контракта. У форка он пустой — не
потому, что кто-то его обнулил, а потому что это другой контракт со своим
storage. Чтобы форк получил принявших, каждый должен подписать его отдельно.

Отсюда и требование называть хэш явно:

```solidity
function adopt(bytes32 core) external {
    if (core != coreHash) revert CoreMismatch(coreHash, core);
```

Кошелёк не может «случайно» оказаться принявшим форк: у форка другой `coreHash`,
и вызов с хэшем оригинала просто откатится.

## Развёртывание

```
coreHash    keccak256 канонических байтов файла со статьями 1–6
coreDigest  sha2-256 тех же байтов — из него собирается IPFS CIDv1
coreURI     ipfs://… — подсказка, где взять текст
bodyHash    keccak256 изменяемой части
bodyURI     ipfs://…
stewards    адрес мультисига
predecessor 0x0 для первой версии, адрес предшественника для форка
```

Хэш считается от **байтов файла**, а не от «смысла текста». Это значит, что
канонический файл должен быть зафиксирован до последнего пробела и перевода
строки: LF, UTF-8 без BOM, финальный перевод строки. Иначе два человека получат
разные хэши одного и того же текста и решат, что произошёл форк.

```bash
# как получить оба значения
keccak-256sum core.md          # или cast keccak $(cat core.md)
sha256sum core.md
```

## Чего этот контракт не делает

Стоит проговорить честно, иначе он превращается в оберег.

**Не делает текст обязательным.** Никого нельзя заставить читать этот адрес.
Контракт не даёт власти — он отнимает возможность соврать о том, что правила
не менялись.

**Не мешает развернуть похожий контракт.** Кто угодно может выкатить свой Canon
с любым текстом и назвать его настоящим. Защита здесь социальная: адрес
оригинала известен, а происхождение форков прослеживается через `predecessor`.

**Не защищает от подмены текста по ссылке.** `coreURI` может однажды начать
отдавать другое. Поэтому проверять нужно `coreHash`, а ссылка — удобство.
IPFS-адресация помогает: CID сам по себе является хэшем.

**Не решает, кто прав.** Если стюарды форкнут ядро и уведут за собой всех
принявших, контракт зафиксирует раскол и на этом остановится. Он делает
изменение видимым, а не невозможным. Разница между «нельзя поменять» и «нельзя
поменять незаметно» — это вся разница, которую даёт код; всё остальное решают
люди.

**Не проверен аудитом.** Это рабочий набросок, не продакшен. Перед деплоем в
основную сеть — тесты, `forge`/`hardhat`, внешний просмотр.
